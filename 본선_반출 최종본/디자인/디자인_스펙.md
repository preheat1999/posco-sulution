# 디자인 스펙 · AI 자재 솔루션

이 문서 하나로 화면의 생김새가 정해진다. 색 · 글자 · 간격 · 부품 · 반응형이
전부 값으로 적혀 있다. 프론트엔드 CLI 에 **가장 먼저** 넣는 문서다.

> 그림(`이미지/*.png`)은 목표를 보여 주고, 이 문서는 **왜 그 모양인지와
> 정확한 값**을 준다. 둘을 같이 줘야 한다. 그림만 주면 「비슷한 것」 이 나오고
> 간격과 상태 변화가 매번 달라진다.

---

## 0. 이 디자인의 성격

사내 업무 화면이다. 예뻐 보이려고 만든 것이 아니라 **담당자가 오늘 무엇을
해야 하는지 3초 안에 찾게** 하려고 만들었다. 그래서

* **흰 카드 + 옅은 회색 배경.** 카드가 정보 단위다. 카드 밖에 정보를 두지 않는다
* **색은 뜻이 있을 때만 쓴다.** 파랑 = 계획품 · 링크 · 지금 할 것,
  빨강 = 보험품 · 늦음, 주황 = 주의 · 핵심설비, 초록 = 정상 · 절감.
  장식으로 색을 쓰지 않는다
* **숫자가 주인공이다.** 큰 숫자 + 작은 단위 + 더 작은 설명, 이 세 줄이 기본형
* **모든 판단에는 근거 버튼이 붙는다.** AI 가 정한 것은 왜 그런지 눌러 볼 수 있다

## 1. 색

### 1.1 토큰 (이 값을 그대로 쓴다)

| 이름 | 값 | 쓰는 곳 |
| --- | --- | --- |
| `--brand` | `#5570F1` | 주색 · 기본 버튼 · 링크 · 선택 상태 |
| `--brand-weak` | `#EEF0FE` | 주색의 연한 배경 · 선택된 메뉴 · soft 버튼 |
| `--bg` | `#F4F5FA` | 페이지 배경 |
| `--surface` | `#FFFFFF` | 카드 · 사이드바 · 입력칸 |
| `--line` | `#F1F2F6` | 아주 옅은 구분선 · 카드 테두리 |
| `--line-2` | `#E4E6EF` | 보통 구분선 · 입력칸 테두리 · 표 머리 밑줄 |
| `--text` | `#1C1D22` | 본문 · 제목 |
| `--text-2` | `#45464E` | 보조 본문 |
| `--muted` | `#8B8D97` | 라벨 · 설명 · 단위 |
| `--insur` | `#CC5F5F` | 보험품 · 마감 초과 · 부족 |
| `--insur-weak` | `#FBEDEE` | 보험품 배지 배경 |
| `--plan` | `#5570F1` | 계획품 (주색과 같은 값) |
| `--plan-weak` | `#EEF0FE` | 계획품 배지 배경 |
| `--core` | `#B26A00` | 주의 · 핵심설비 · 이번 주 |
| `--core-weak` | `#FDF3E3` | 주의 배지 배경 |
| `--ok` | `#32936F` | 정상 · 절감 · 완료 |
| `--ok-weak` | `#E7F4EF` | 정상 배지 배경 |

### 1.2 절대 규칙

* **순수 검정 `#000` 금지.** 가장 진한 색은 `#1C1D22` 다.
  검정은 화면에서 구멍처럼 보이고 눈이 피로하다
* 색을 새로 만들지 않는다. 필요하면 위 목록 중에서 고른다
* 배지는 반드시 `-weak` 배경 + 진한 글자 조합이다. 진한 배경에 흰 글자를
  쓰는 배지는 없다 (버튼과 헷갈린다)

### 1.3 그림자와 모서리

```
--radius : 16px                     카드
--shadow : 0 1px 2px rgba(28,29,34,.04),
           0 8px 24px rgba(28,29,34,.05)
```

버튼 10px · 작은 버튼 8px · 배지 7px · 알약 999px · 입력칸 10px ·
스테퍼 카드 12px · 모달 16px.

그림자는 카드에만 쓴다. 배지 · 버튼 · 입력칸에는 그림자가 없다.

## 2. 글자

```
font-family : "Malgun Gothic", "Apple SD Gothic Neo", system-ui, sans-serif
base        : 14px / 1.55
```

웹폰트를 쓰지 않는다. 사내망에서 폰트 주소가 막히면 글자가 통째로 바뀐다.

| 자리 | 크기 | 굵기 | 색 |
| --- | --- | --- | --- |
| 화면 제목 `h1` | 21px (모바일 18px) | 700 | `--text` |
| 빵조각 `.crumb` | 11.5px | 400 | `--muted` |
| 카드 제목 `h2` | 15px | 700 | `--text` |
| 카드 부제 `.sub` | 11.5px | 400 | `--muted` |
| KPI 숫자 `.v` | 20px | 700 | 뜻에 따라 |
| KPI 단위 `small` | 12px | 600 | `--muted` |
| KPI 라벨 `.k` | 11.5px | 400 | `--muted` |
| 본문 | 13~13.5px | 400 | `--text-2` |
| 표 머리 | 11px | 700 | `--muted` |
| 표 본문 | 12.5px | 400 | `--text` |
| 배지 | 11px | 700 | 뜻에 따라 |
| 버튼 | 13px (sm 12px) | 600 | |
| 잔글씨 `.note` | 11px / 1.7 | 400 | `--muted` |

자간은 큰 글자에만 준다. `h1 -0.4px` · KPI 숫자 `-0.6px` · 카드 제목 `-0.2px`.

**숫자는 `font-variant-numeric: tabular-nums`.** 표에서 자릿수가 흔들리면
비교가 안 된다.

## 3. 레이아웃

### 3.1 뼈대

```
.layout  grid  [사이드바 230px][본문 1fr]   min-height:100vh
  .side   흰 배경 · 오른쪽 1px 선 · sticky top:0 · height:100vh · 세로 스크롤
  .main   padding 22px 26px 56px · min-width:0
    .top        상단 바 (제목 + 우측 도구)
    .infobar    설명 배너 (접힘)
    .kpiwrap    KPI 묶음
    section.card 본문 카드들
.overlay  햄버거용 어두운 막 (fixed inset:0, rgba(28,29,34,.42))
```

`min-width:0` 이 없으면 grid 자식이 내용 너비만큼 벌어져 가로 스크롤이 생긴다.

### 3.2 상단 바

```
.top          flex · space-between · gap 14px · margin-bottom 18px
  .top-left   flex · gap 12px · min-width:0
    button.hamb   36x36 · 960px 이하에서만 보임
    div > .crumb + h1
  .top-right  flex · gap 10px · flex:none
    .pill  요약 알약   .btn  도구 버튼   .avatar  36px 원형
```

> **함정 · 실제로 당했다.** `.top-right{flex:none}` 이라 절대 줄지 않는데
> `.top-left{min-width:0}` 이라 0 까지 눌린다. 430px 에서 제목이
> 「속 / 성 / 값 / 판 / 단」 처럼 한 글자씩 세로로 쌓였다.
> **760px 이하에서는 두 줄로 내린다.**
> ```
> .top{flex-wrap:wrap; align-items:flex-start; row-gap:10px}
> .top-left{width:100%}
> .top-right{width:100%; flex:1 1 100%; flex-wrap:wrap; justify-content:flex-start}
> ```

### 3.3 사이드바

`nav.js` 하나가 그린다. 페이지는 빈 `<aside class="side" id="side">` 와
`window.PAGE` 값만 둔다. 사이드바 HTML 을 페이지에 복사하면 안 된다.
메뉴가 바뀔 때 13곳을 고치게 된다.

메뉴 3그룹 · 그룹 라벨은 10.5px / 700 / letter-spacing .06em / `--muted`.

```
관리   Dashboard(main)         자재 검색 POS APPIA(search)
분석   속성값 판단(attr)        적정재고 분석(stock)        정비계획 소요 발주(plan)
       주간 리포트(report)
업무   구매신청 PR(purchase)    자재반납 QR(return)
```

선택된 항목은 `--brand-weak` 배경 + `--brand` 글자 + 700.
항목 오른쪽에 숫자 배지를 붙일 수 있다 (해야 할 건수).

## 4. 부품

### 4.1 카드

```
.card  흰 배경 · 1px --line 테두리 · radius 16 · --shadow
       padding 18px 20px · margin-bottom 16px
.card > header   flex · space-between · align-items:flex-start · margin-bottom 14px
       왼쪽  h2 (+ .sub 부제)
       오른쪽 배지 · 버튼 · 접기 화살표
```

### 4.2 KPI

```
.kpiwrap   grid  1.5fr 1fr 1fr · gap 16 · margin-bottom 16
.kpigroup  카드와 같은 껍데기 · padding 16px 18px
  p.gt     묶음 제목 11.5px/700/--muted · 앞에 ✦ (--brand)
           오른쪽 끝에 「바로가기」 링크 11px/700/--brand
  .row > .kpi     숫자 묶음 (flex:1)
     .v  20px/700   .v small  12px/600/--muted   .k  11.5px/--muted
```

`.kpi.insur .v` 는 빨강, `.plan` 파랑, `.core` 주황, `.ok` 초록.
**숫자에 색이 붙으면 그 색의 뜻이 그대로 적용된다.** 아무 색이나 쓰지 않는다.

`a.kpigroup` 은 hover 에 테두리가 주색으로 바뀌고 1px 떠오른다.

### 4.3 버튼

**`.btn` 자체가 파란 기본 버튼이다.** 변형은 셋뿐이다.

| 클래스 | 배경 | 글자 | 테두리 |
| --- | --- | --- | --- |
| `.btn` | `--brand` | 흰색 | `--brand` |
| `.btn.soft` | `--brand-weak` | `--brand` | 투명 |
| `.btn.line` | `--surface` | `--text-2` | `--line-2` |
| `.btn.sm` | (위와 조합) padding 6px 11px · 12px · radius 8 | | |

```
기본  inline-flex · gap 6 · radius 10 · padding 9px 15px · 13px/600
hover filter:brightness(.95)
```

**`.btn-primary` 같은 클래스는 만들지 않는다.** 이름이 늘어나면 어느 것이
기본인지 모르게 된다.

### 4.4 배지

```
.badge  inline-flex · gap 4 · 11px/700 · padding 3px 8px · radius 7
        기본 배경 --line / 글자 --text-2
        .insur .plan .core .ok  각각 -weak 배경 + 진한 글자
        white-space: nowrap      <- 반드시
```

> **함정.** flex 자식은 `min-width:auto` 라 min-content 폭까지 줄어든다.
> 한글은 글자마다 줄바꿈이 되므로 min-content 가 **한 글자**다.
> nowrap 이 없으면 「변경」 이 「변 / 경」 으로 쌓인다.
> 칩 · 알약 · 배지 · 탭에는 전부 nowrap 을 준다.

### 4.5 표

```
.tablewrap        overflow-x:auto
.tablewrap.tall   max-height min(52vh,560px) · overflow auto   (긴 표에만)
table             width 100% · border-collapse collapse · 12.5px
thead th          왼쪽정렬 11px/700/--muted · padding 8px 10px
                  border-bottom 1px --line-2 · nowrap
tbody td          padding 11px 10px · border-bottom 1px --line
td.num            오른쪽 정렬 · tabular-nums
.linkq            주색 700 + 아래 점선 (누르면 자재 상세로)
```

`.tall` 일 때 `thead th` 를 `position:sticky; top:0` 로 고정한다.
**`thead` 나 `tr` 에는 sticky 가 걸리지 않는다. `th` 에 걸어야 한다.**
스크롤에 밑줄이 먹히지 않게 배경을 채우고 `box-shadow: inset 0 -1px 0` 로 선을 만든다.

### 4.6 설명 배너

```
.infobar  flex · gap 10 · --brand-weak 배경 · radius 12 · padding 13px 16px
          12.5px/1.65 · --text-2 · margin-bottom 16
          기본은 첫 줄만 (max-height 1.78em, overflow hidden)
          오른쪽 위에 「자세히」 알약, 누르면 펼침 (「접기」 로 바뀜)
```

왜 이렇게 만들었는지는 처음 한 번만 궁금하다. 매 화면에서 세로 60px 을 돌려받는다.

### 4.7 진행 파이프라인

선형 진행이 아니라 **단계마다 건이 쌓이는** 모양이다.
연결선이 흐름, 동그라미가 단계, 숫자가 그 단계에 걸린 건수.
가장 많이 걸린 단계는 병목(`jam`)으로 표시한다.

```
데스크톱  가로 · grid-auto-flow:column
모바일    세로 · [동그라미] [단계명 / 부제] [건수]
          자리를 직접 지정한다. 자동 배치에 맡기면 단계명이 반으로 쪼개진다
동그라미  32px 원 · 기본 흰 배경 + --line-2 테두리
          .doing  --brand 테두리 + --brand-weak 배경
          .done   --ok 채움 + 흰 체크
```

### 4.8 건강도 얼굴

발주 마감 목록에 30x30 얼굴을 붙인다. **색만으로 구분하지 않는다.**
색약인 사람도 표정으로 알 수 있어야 한다.

| 남은 일수 | 표정 | 색 |
| --- | --- | --- |
| 7일 이상 | 웃음 | `--ok` |
| 3~6일 | 무표정 | `--core` |
| 2일 이하 · 초과 | 찡그림 | `--insur` |

### 4.9 모달

```
.modal-back  fixed inset:0 · rgba(28,29,34,.42) · z-index 60 · padding 20 · 세로 스크롤
.modal       흰 배경 · radius 16 · max-width 470 · padding 20px 22px
             box-shadow 0 20px 60px rgba(28,29,34,.22)
             header: h3 15px/700 + 닫기 x (19px, --muted)
```

### 4.10 근거 팝오버

AI 가 정한 값 옆에는 `?` 버튼을 둔다. 누르면 산식 · 점수 · 원본값이 나온다.
**근거를 숨기지 않는 것이 이 서비스의 핵심**이라 모든 판정에 붙인다.

## 5. 반응형 3단계

| 폭 | 무엇이 바뀌나 |
| --- | --- |
| `1180px` | 다열 그리드를 2열로 · 스테퍼 줄바꿈 |
| `960px` | **사이드바를 햄버거 오버레이로** · 본문 padding 16px · 2열을 1열로 |
| `760px` | **상단 바를 두 줄로** · 탭 줄바꿈 |
| `640px` | **표를 카드로** · KPI 1열 · 제목 18px |

### 5.1 표를 카드로 바꾸는 방법

```
thead 를 숨긴다
table, tbody, tr, td 를 전부 display:block · width:100%
tr  1px --line-2 테두리 · radius 12 · padding 6px 12px · margin-bottom 10px
td  flex · space-between · gap 14 · text-align right
    td::before { content: attr(data-label) }  <- 왼쪽 라벨
    flex-wrap: wrap        자리 없으면 줄을 넘긴다
    td > span { flex:none } 칩이 한 글자로 눌리지 않게
```

**모든 `td` 에 `data-label` 을 넣어야 한다.** 하나라도 빠지면 카드에서
그 값이 무엇인지 알 수 없다.

### 5.2 긴 목록 (반드시 지킬 것)

`.tablewrap.tall` 은 카드 모드에서 안쪽 스크롤을 없앤다. 스크롤 안에
스크롤이 있으면 손가락으로 못 쓴다.

> **그런데 그러면 743행이 카드 743장으로 그대로 펼쳐진다.**
> 실측 · 속성값 판단 화면이 430px 에서 **문서 높이 189,000px**,
> 적정재고가 **204,000px** 이 나왔다. 폰에서 못 쓴다.
>
> **좁은 화면에서는 처음 20장만 그리고 「더 보기 (남은 723건)」 버튼을 둔다.**
> 누르면 20장씩 늘린다. 필터와 검색이 있으니 전부 펼칠 이유가 없다.
> 데스크톱은 지금처럼 안쪽 스크롤로 둔다.

### 5.3 세로가 짧은 화면

본선 시연은 와이드 화면이다. 가로는 이미 다 쓰므로 세로를 줄인다.

```
@media (max-height:1000px)  카드 padding 15px 17px · 본문 padding 16px 26px
                            KPI 숫자 22px · 카드 사이 12px
@media (max-height:820px)   .tablewrap.tall 을 min(46vh,420px) 로
```

1920x1080 과 1366x768 에서 실제로 찍어 보고 넘치는 것을 하나씩 눌렀다.

## 6. 상호작용

| 동작 | 규칙 |
| --- | --- |
| 클릭 대상 | 최소 36x36px. 모바일은 44x44px 권장 |
| hover | 카드는 테두리가 주색으로, 버튼은 `brightness(.95)` |
| 포커스 | `:focus-visible` 에만 링을 준다 (`2px solid --brand`, offset 2px). 마우스 클릭에는 링이 안 나온다 |
| 전환 | `.12s ~ .18s ease`. **`prefers-reduced-motion` 을 존중한다** |
| 빈 상태 | 「없음」 이 아니라 **무엇을 하면 되는지** 적는다 (「QR 을 스캔하거나 Q코드를 입력해 반납할 자재를 추가하세요」) |
| 로딩 | 스피너 대신 단계 문구를 보여 준다 (챗봇은 실측 평균 31초) |
| 실패 | 원인을 나눠서 알려 준다 (코드 없음 / 형식 아님 / 등록되지 않은 자재) |

## 7. 글쓰기 규칙

* **em-dash(U+2014) 와 en-dash(U+2013) 를 쓰지 않는다.** 가운뎃점 `·` 을 쓴다
* 숫자에는 단위를 붙인다. `120품목` `29.71억원` `마감 332일 초과`
* 금액은 만원과 억원을 섞지 않는다. 1억 넘으면 억원, 아니면 만원
* 라벨은 명사, 버튼은 동사. 「발주 필요」 / 「발주 필요 목록 보기」
* AI 가 정한 값에는 반드시 「AI」 표시나 근거 버튼을 붙인다.
  사람이 정한 값과 구분되지 않으면 신뢰가 무너진다
* 회색지대는 화면에서 **「현행유지」** 로 순화한다.
  「일치 확인」 이 아니라 「판단 보류」 라는 뜻이므로 신뢰도를 함께 낸다

## 8. 접근성

* 모든 아이콘 버튼에 `aria-label`
* 표의 카드 모드는 `data-label` 이 라벨 역할을 한다
* 색만으로 뜻을 전하지 않는다 (얼굴 · 글자 · 화살표를 함께)
* 대비 · `--muted #8B8D97` 는 흰 배경에서 3.5:1 이다.
  **본문에 쓰지 말고 라벨과 설명에만 쓴다**
* 키보드로 모든 버튼에 닿을 수 있어야 한다

## 10. 화면별 그림

`이미지/` 폴더에 26장이 있다. `_pc.png` 는 1512px, `_mobile.png` 는 430px.
**두 장을 나란히 보면 반응형 규칙이 눈에 보인다.**

프롬프트에 넣는 순서

1. 이 문서 (디자인 스펙)
2. `와이어프레임/` 의 해당 화면 문서
3. `이미지/` 의 `_pc.png` 와 `_mobile.png`

그림의 숫자는 **목표가 아니라 예시**다. 숫자는 DB 에서 읽는다고 반드시 적어 준다.
