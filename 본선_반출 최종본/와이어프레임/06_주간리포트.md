## 무엇을 하는 화면인가

**리더가 화면에 들어오지 않아도** 자기 부서 자재 현황을 알게 한다.
속성 불일치 · 재고부족 · 과잉재고를 한 통에 담고,
이번 주에 손대야 할 항목만 앞으로 뺀다.

이 화면이 있는 이유 · 담당자는 매일 들어오지만 **리더는 안 들어온다.**
리더가 안 보면 승인이 안 나고, 승인이 안 나면 라벨이 안 쌓인다.

## 왼쪽 · 발송 설정

| 영역 | 내용 |
| --- | --- |
| 발송 방식 | 「메일 앱 열기(설정 없음)」 / 「EmailJS」 |
| 대상 부서 | 부서 선택. 아래에 `전체 N품목 · 알고리즘 확정 N품목 · 확정률 %` |
| 수신자 | 선택된 사람이 칩으로. x 로 뺀다. 부서 외 수신자는 주황 칩 |
| 조직 트리 | 파트 → 섹션 → 사람. 체크박스. 사람마다 역할 배지 |
| 외부 주소 | 심사위원 메일을 직접 넣는 칸 (시연용) |
| 제목 · 내용 | 담을 섹션 4개 체크 |
| 주기 · 시각 | 요일 버튼 + 시각 |

> **「확정률」 이라고 쓴다. 「일치도」 가 아니다.**
> 알고리즘이 보험품/계획품으로 **확정한 비율**이지, 원본과 판정이 **같다**는
> 뜻이 아니다. 회색지대는 확정이 아니므로 정본 Type 을 유지한다.
> 말을 잘못 쓰면 심사위원이 정확도로 읽는다.

조직 트리는 **로그인 화면과 같은 데이터**(`org.js`)를 쓴다.

## 오른쪽 · 메일 미리보기

받는 사람이 보게 될 **실제 HTML** 을 그대로 보여 준다.

| 버튼 | 하는 일 |
| --- | --- |
| HTML 복사 | Outlook 본문에 붙여넣으면 표와 색이 살아난다 |
| 텍스트 복사 | 서식 없는 본문 |
| .html 내려받기 | 파일로 저장 |
| 메일 앱으로 열기 | `mailto:` · **텍스트 본문으로만 열린다** |

**메일 프로토콜이 HTML 본문을 허용하지 않아서** 네 갈래가 필요하다.
이 사정을 미리보기 아래에 적어 둔다. 안 적으면 「왜 색이 없어요?」 를 듣는다.

메일 본문 구성

1. 머리 · 부서 · 기간 · 생성 시각
2. KPI 5칸 · 발주 마감 초과 / 속성 불일치 / 재고부족 / 과잉재고 / 기대 절감
3. 이번 주 조치 필요 · 급한 순 카드. 각 카드에 **왜 급한지 한 줄**
4. 선택한 섹션들의 요약 표

## 데이터 출처

전부 DB 요약과 어댑터에서 온다. **메일 본문에 숫자를 적어 두지 않는다.**

| 값 | 출처 |
| --- | --- |
| 발주 마감 초과 | 정비 일정에 묶인 건 중 `dDays <= 0` |
| 속성 불일치 | `bucket['보험품→계획품'] + bucket['계획품→보험품']` |
| 재고부족 · 과잉재고 | `summary.action` 의 발주 · 감축 |
| 기대 절감 | `(감축액 + 공용화 회수액) x 0.20 x 0.046` |
| 수신자 | `org.js` |

**기대 절감은 두 값이 있다.** 부서 기준 3,604만원 · 전사 기준 18.5억원.
어느 모집단인지 반드시 붙여 쓴다.
