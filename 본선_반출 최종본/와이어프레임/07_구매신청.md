## 무엇을 하는 화면인가

**두 시스템에 같은 내용을 두 번 입력해야 한다.**
정비부서 일반자재는 설비관리시스템(EAM)에서 PR 을 발행하면 ERP PR 로
연계되며 Destination Type 이 Inventory 로 자동 지정된다.
AI 가 두 시스템의 입력 항목을 **한 번에** 완성한다.

## 목록

| 열 | 내용 |
| --- | --- |
| 자재명 | 정본 품명 |
| Q코드 | 자재코드 |
| 속성 | 보험품 / 계획품 / 소모품 / 순환품 배지. **배제 판정은 소모품 · 순환품으로 표시** |
| 구매 가능 | `ACTIVE`(초록 글자) / `[INACTIVE]`(빨강 배지) |
| 수량 | 신청 수량 |
| 예상금액 | 1억 넘으면 억원, 아니면 만원 |
| 작성 상태 | `[작성 완료]`(초록) / `[확인 필요]`(빨강) |

행을 누르면 아래 상세와 ①~⑤ 초안이 그 자재로 채워진다.
선택된 행은 왼쪽에 파란 막대 + 연한 배경.

**작성 상태 판정** · `구매 가능하고 주의가 2건 이하면 작성 완료`.
INACTIVE 이거나 주의가 많으면 확인 필요.

## 진행 막대 (`wflow.js`)

```
① PR 초안        AI 자동작성 · 두 시스템 동시
② 규칙 검증       필수 항목 · 규칙 모두 통과
③ 시스템 입력     지금 실행할 수 있습니다
④ 승인요청        저장 후 WMATL
```

끝난 단계는 초록 체크, 지금 할 단계는 파란 번호, 남은 단계는 회색.
막대 아래에 **지금 무엇을 하면 되는지 한 문장**을 초록 배경으로 둔다.

## ① 설비관리시스템 PR 초안 / ② ERP PR 초안

실제 입력 화면의 항목을 그대로 나열한 폼. **AI 가 채운 칸에는 `AI` 표시**를 붙인다.
사람이 고칠 수 있어야 한다. 읽기 전용 칸(자재코드 · 단가)은 회색.

## ③ AI 규칙 검증

규칙마다 통과 / 주의 / 실패. 주의에는 **왜 주의인지와 어떻게 하면 되는지**를 적는다.
예 · 「Destination Type 이 Inventory 가 아닙니다. 정비부서 일반자재는
Inventory 로 지정해야 합니다.」

## ④ 시스템 자동 입력 실행

Claude Agent Skill + Selenium 으로 두 시스템에 직접 입력한다.
**저장 직전에 멈춘다.** 실행 로그를 한 줄씩 보여 주고 마지막에 사람이 누른다.

> 자동화가 사람 대신 저장까지 해 버리면 아무도 안 쓴다.
> **사람의 판단 자리를 남기는 것**이 이 화면의 설계 원칙이다.

## ⑤ 수동 입력 도우미

권한이 없을 때 쓴다. 항목별 복사 버튼 + CSV 내려받기.
탭으로 설비관리시스템 / ERP 를 전환한다.

## 데이터 출처

| 값 | 출처 |
| --- | --- |
| 품명 · 단가 · 리드타임 · 속성 · 등급 · 목표재고 | 정본 `DB.item()` |
