---

## 우선순위대로 만드는 이유

시간이 모자랄 때 무엇을 포기할지 미리 정해 둔다.

| 순위 | 무엇 | 없으면 |
| --- | --- | --- |
| 1 | 공통 셸 | 아무것도 못 만든다 |
| 2 | 대시보드 · 속성값 판단 · 적정재고 | **시연이 안 된다.** 이 셋이 과제의 답이다 |
| 3 | 정비계획 · 구매신청 · 반납 · QR 2종 · 로그인 | 흐름이 끊긴다 |
| 4 | 리포트 · 검색 · 근거 | 아쉽지만 말로 설명할 수 있다 |

## 프롬프트에 넣는 순서

```
1  디자인/디자인_스펙.md            <- 색 · 글자 · 간격 · 부품 · 반응형
2  와이어프레임/00_공통셸.md          <- 껍데기
3  와이어프레임/<해당 화면>.md         <- 영역 · 데이터 출처 · 상호작용
4  이미지/<화면>_pc.png + _mobile.png <- 최종 모습
```

**한 번에 화면 하나씩** 만든다. 세 개를 한꺼번에 시키면 셸이 화면마다 달라진다.

---

## 도면 읽는 법

```
┌─┐ │ └  카드와 영역 경계
[  ]     버튼 · 배지 · 입력칸
▎        선택된 행의 왼쪽 막대
∧ ∨      아코디언 열림 / 닫힘
✦        AI 가 낸 값이라는 표시
🙂😐😖    건강도 얼굴 (초록 / 주황 / 빨강)
```

도면 안의 **숫자는 예시**다. 전부 DB 에서 읽는다.
화면에 숫자를 적어 두면 데이터가 바뀔 때 요약만 옛날 값으로 남는다.
