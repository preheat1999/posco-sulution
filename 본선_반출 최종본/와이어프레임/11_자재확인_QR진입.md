# 와이어프레임 11 · 자재 확인 (`material-view.html`)

**공통 셸을 쓰지 않는다.** 폰으로 QR 을 찍었을 때 열리는 화면이다.
그림 · `이미지/material-view_pc.png` · `이미지/material-view_mobile.png`

---

## 무엇을 하는 화면인가

자재에 붙은 **자재식별표 QR** 을 폰 기본 카메라로 찍으면 바로 열린다.
전용 앱도 카메라 권한도 필요 없다. 주소가 이렇게 생겼다.

```
https://<호스트>/material-view.html?code=Q4039953
```

**한 자재만 보여 준다.** 여기서 「반납」 을 누르면 반납 초안으로 이어진다.

## 자재식별표 QR 카드 (접힘)

펼치면 이 자재의 QR 을 **화면에서 직접 그려** 보여 주고
「JPG 내려받기」 버튼을 준다. 자재식별표를 새로 인쇄할 때 쓴다.

QR 은 직접 구현한다 (ISO/IEC 18004 Model 2 · 바이트 모드 · v1~10 · L/M/Q/H).
외부 라이브러리 없이 그린다.

> **함정 · 실제로 당했다.** 형식정보 15비트를 **LSB 부터** 배치해서
> 순서가 통째로 뒤집혔다. 파인더 패턴은 찾히는데 마스크 번호를 못 읽어
> 디코드가 실패했다. **내가 만든 왕복 시험은 이걸 잡지 못했다.**
> 인코더와 디코더가 같은 비트 순서 가정을 공유했기 때문이다.
> **자기 가정끼리 대조하면 아무것도 검증되지 않는다.**
> 규격에 실린 값이나 남이 만든 구현(zxing · segno · OpenCV)과 대조해야 한다.

## 아래 고정 버튼

`[취소]` `[반납]` 두 개. 반납을 누르면
「Q4039953 자재를 반납처리하겠습니까?」 확인 후
`mobile-return.html?code=...&from=qr` 로 넘어간다.
**스캔 단계를 건너뛰고 2단계(반납 초안)부터 시작한다.**

## 오류 처리 (세 갈래를 구분한다)

| 상황 | 화면 |
| --- | --- |
| `?code=` 가 없다 | 「자재코드가 없습니다」 + 직접 입력칸 + 예시 코드 칩 |
| 형식이 아니다 | 「자재코드 형식이 아닙니다」 + 형식 설명 |
| 정본에 없다 | 「등록되지 않은 자재입니다」 + 코드 표시 |

**셋을 하나로 뭉치지 않는다.** 현장에서 무엇을 고쳐야 할지가 달라진다.

주소는 `?code=` `?q=` `#Q0000000` 세 형태를 모두 받는다.
QR 리더마다 붙이는 방식이 다르다.

## 데이터 출처

`DB.item(code)` 하나. 부서 경로는 `DB.dept()`, 담당자는 조직 트리(`org.js`),
단위는 업무 태그(`DB_BIZ.tags`), 반납 가능 여부는 반납 대장.

> **함정 · 실제로 당했다.** 반납 대장을 만드는 어댑터를 DB 보다 **먼저**
> 로드하면 빈 배열이 만들어지고 **오류도 나지 않는다.**
> 화면은 조용히 「반납 대장 없음」 을 띄운다. 스크립트 순서를 지킨다.
