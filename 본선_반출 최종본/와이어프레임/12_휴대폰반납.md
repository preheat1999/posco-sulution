# 와이어프레임 12 · 휴대폰 반납 (`mobile-return.html`)

**공통 셸을 쓰지 않는다.** 폰 전용 3단계 화면이다.
그림 · `이미지/mobile-return_pc.png` · `이미지/mobile-return_mobile.png`

---

## 무엇을 하는 화면인가

현장에서 폰으로 반납을 끝내는 화면. **3단계**로 나눈다.

```
1 스캔 · 자재를 고른다 (QR 로 들어오면 건너뛴다)
2 확인 · AI 초안을 보고 수량을 정한다
3 완료 · 결과와 다음 할 일
```

자재 확인 화면에서 넘어오면 **2단계부터 시작한다.**

## 규격

| 요소 | 값 |
| --- | --- |
| 진행 막대 | 3칸. 완료 칸은 `--brand`, 남은 칸은 `--line-2` |
| AI 표시 | 값 오른쪽에 작은 `AI` 배지. **사람이 고칠 수 있다** |
| 주의 표시 | 주황 `주의` 배지 + 아래 한 줄 설명 |
| 수량 스텝퍼 | `－` `숫자` `＋`. 버튼 44x44px. 아래에 불출 잔여 |
| 아래 버튼 | 화면 하단 고정. 좌 `.btn line` 1fr, 우 `.btn` 2fr |
| 터치 영역 | 최소 44x44px |

**Account 에 반드시 주의 배지를 붙인다.** 현장 최다 실수다.
「반드시 최초 불출 계정과 동일해야 합니다」 를 값 아래에 적는다.

## 「AI가 이렇게 판단한 이유」

펼치면 판정 근거를 준다.

```
불출일이 2026-09-01 로 당월입니다        -> 당월 신품반납
물품 상태가 신품입니다                    -> 거래 Q00101
불출 창고가 PFC(QFC01) 입니다            -> 원 창고로 반납
당월 불출 · 신품 · 동일 계정이므로 결재가 필요 없습니다
```

## 데이터 출처

| 값 | 출처 |
| --- | --- |
| 품명 · 단가 · 창고 | 정본 `DB.item()` |
| 불출일 · 상태 · 잔여 · 계정 · 위치 | 업무 `DB_BIZ.returns` |
| 반납 유형 · 창고 · 결재 | 업무 규칙 함수 |

반납 처리 = `DB.txn({ q, type:'반납', qty })`.
3층에 이력이 쌓이고 현재고가 그만큼 늘어난다.
**적정재고 화면의 조치가 즉시 바뀐다** (발주 → 유지).
