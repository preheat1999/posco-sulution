## 무엇을 하는 화면인가

**정비 정보가 네 곳에 흩어져 있다.**
일정은 MES 에, 수리 대상은 WO 에, 실제 작업 내용은 현장 엑셀에,
확정 사항은 메일에 있다. 어느 하나만 봐도 필요한 자재를 알 수 없어서
대수리마다 급하게 찾는다.

이 화면은 넷을 하나로 묶어 **필요한 자재와 발주 시점**을 낸다.

```
발주 마감일 = 정지시작일 - (리드타임평균 + 선행일수 + 0.5 x 리드타임편차)
선행일수 · 합리화 60 · 대수리 45 · 중수리 21 · 정기수리 14 · 교체휴지 10 · 공정휴지 7
```

## ① 타임라인 카드

한 줄이 WO 하나다. 왼쪽에 색 막대(상태색) + 얼굴, 오른쪽에 남은 일수.

| 요소 | 내용 |
| --- | --- |
| 얼굴 | 30px · 7일↑ 웃음(초록) / 3~6일 무표정(주황) / 2일↓·초과 찡그림(빨강) |
| 제목 | 설비명 + `[휴지구분]` 배지 + WO 번호 (muted) |
| 부제 | `작업내용 미확인 · 자재 8종 · 발주 필요 3종 · 평균 리드타임 139일` |
| 가운데 | 정비 예정일을 가리키는 얇은 타임라인 막대 |
| 오른쪽 | `초과 287일` / `D-4` / `자재 확보` + 아래 작은 글씨로 마감일 |

**「자재 확보」 는 마감일이 없는 상태다.** 재고와 이관으로 충당된다는 뜻.

> **함정 · 실제로 당했다.**
> 1. `null < 3` 이 참이라 자재 확보 건이 「지금 신청」 으로 세어졌다 (4건 → 6건)
> 2. 라벨 함수를 안 쓰고 값을 직접 이어 붙여 **「마감 D-null」** 이 화면에 나왔다
>
> 날짜와 남은 일수는 **반드시 라벨 함수 하나를 거쳐** 출력한다.

「작업내용 미확인」 이 대부분인 것은 버그가 아니다.
**실데이터에서 작업내용 채움률이 0.0% 였다.** 그것을 숨기지 않고 적는다.

## ② 정비 정보 지식 그래프

네 출처(MES 일정 · WO 수리대상 · 현장 엑셀 · 메일)를 개체와 관계로 잇는 그림.
**직접 그린다.** 개체 18 · 관계 28 정도의 작은 그래프다.
각 개체에 출처 색을 다르게 주고, 관계선에 신뢰도를 붙인다.

## ③ 정비계획별 소요 자재

WO 를 고르면 그 WO 의 소요 자재 목록이 열린다.
자재마다 **왜 이 자재가 필요하다고 봤는지**(과거 불출 이력 · 설비 BOM ·
작업명 키워드 · 메일문)와 신뢰도를 붙인다.

## ④ 이관 요청 · PR 신청

부족한 자재를 **타부서에서 이관**받거나 **PR 을 올린다.**
이관이 가능하면 그쪽을 먼저 권한다 (사는 것보다 싸다).

## 데이터 출처

정비계획 데이터는 **생성기가 만든다.** 화면에서 마감일을 계산하지 않는다.

| 영역 | 출처 |
| --- | --- |
| WO · 휴지 일정 | `DB.maintenance()` |
| 소요 자재 | 생성기가 낸 WO 별 자재 목록 |
| 마감일 · 남은 일수 | 생성기가 계산한 값 (`dueDate` `dDays`) |
| 리드타임 | 정본 `ltMean` `ltStd` |

**선행일수 6종을 화면과 생성기가 각각 들고 있으면 안 된다.**
실제로 검사기 쪽 값만 옛날 것(교체휴지 14 · 공정휴지 없음)으로 남아 있었다.
지금 WO 가 합리화와 대수리뿐이라 드러나지 않았을 뿐이다.
