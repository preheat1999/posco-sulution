## 각 영역 규격

### KPI 묶음 3개 (`.kpiwrap` · grid `1.5fr 1fr 1fr`)

| 묶음 | 숫자 | 색 |
| --- | --- | --- |
| 담당 현황 | 담당 설비 수 · 담당 자재 종수 · 보유 재고액 | 기본 |
| ✦ AI 속성 분류 | 보험품→계획품 · 계획품→보험품 · 회색지대 | 파랑 · 빨강 · 기본 |
| ✦ AI 적정재고 분석 | 발주 필요 · 감축 대상 | 주황 · 초록 |

`✦` 는 AI 가 낸 값이라는 표시다. 오른쪽 끝에 「바로가기」 링크를 둔다.
묶음 전체가 링크(`a.kpigroup`)라 hover 하면 테두리가 주색으로 바뀐다.

### 오늘 할 일 (`.todo`)

네 종류. 왼쪽에 시급도 딱지, 오른쪽에 문장 + 행동 버튼.

| 딱지 | 색 | 뜻 |
| --- | --- | --- |
| 지금 | `--insur` | 마감을 이미 넘긴 것 |
| 이번 주 | `--core` | 이번 주에 해야 할 것 |
| 기회 | `--ok` | 안 해도 되지만 하면 돈이 남는 것 |
| 검토 | 기본 | 사람이 판단해야 할 것 |

문장 안의 **숫자만 16px / 700 / 딱지 색**으로 키운다.
「지금」 항목에는 가장 급한 건의 이름과 이유를 한 줄 더 붙인다.

> **함정 · 실제로 당했다.** 자바스크립트에서 `null < 3` 은 **참**이다.
> 마감일이 없는 건(자재 확보 완료)을 「지금 신청」 으로 세어 4건이 6건이 됐다.
> **null 을 먼저 걸러라.**

### 발주 마감일 (`.due`)

30x30 얼굴 + 자재명/설비 + 오른쪽에 남은 일수와 마감일.

| 남은 일수 | 얼굴 | 색 |
| --- | --- | --- |
| 7일 이상 | 🙂 웃음 | `--ok` |
| 3~6일 | 😐 무표정 | `--core` |
| 2일 이하 · 초과 | 😖 찡그림 | `--insur` |

**색만으로 구분하지 않는다.** 표정과 글자를 함께 낸다.

### 진행 파이프라인 (`.pipe`)

선형 진행이 아니라 **단계마다 건이 쌓이는** 모양이다.
동그라미를 누르면 그 단계에 걸린 건이 아래에 펼쳐진다.
가장 많이 걸린 단계는 병목으로 표시한다.

```
구매신청  작성(DRAFT 계획수립) · 승인(WAPPR1·WAPPR2) · 구매(WMATL·PMATL·APPR) · 완료(RELEASED)
자재반납  QR스캔(자재식별표 인식) · 유형판정(AI 7갈래) · 결재(부내결재·자재구매그룹) · 입고완료
```

### 설비별 자재 현황

`설비 · 자재` / `속성` / `보유 → 목표` / `조치` 4열.
보유 숫자가 링크(`.linkq`)라 누르면 창고별 위치와 타부서 보유가 열린다.

## 데이터 출처

**화면에 자재를 직접 적지 않는다.** 전부 DB 에서 읽는다.

| 영역 | 출처 |
| --- | --- |
| 담당 현황 | `DB.summary()` · `DB.equipment()` |
| AI 속성 분류 | `DB.summary().bucket` |
| AI 적정재고 | `DB.summary().action` · `nowAmt` `cutAmt` |
| 오늘 할 일 | 위 요약을 문장으로 바꾼 것 |
| 발주 마감일 | 정비 일정에 묶인 건 (`dDays` 오름차순) |
| 진행 파이프라인 | 업무 거래 상태 (`DB_BIZ`) |
| 설비별 자재 | `DB.list()` 를 설비로 묶은 것 |

**요약 숫자를 화면에 적어 두지 않는다.** 매번 다시 센다.
데이터가 바뀌면 요약만 옛날 값으로 남는 사고가 난다.
