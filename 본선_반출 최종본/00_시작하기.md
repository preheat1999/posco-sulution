# 00 · 시작하기 · 본선 당일 진행 안내

**아침에 이 문서부터 연다.** 순서대로만 하면 된다.
개발을 모르는 상태로 읽어도 되게 썼다.

---

## 0. 5분 안에 알아야 할 것

```
오늘 할 일   빈 노트북에서 웹앱을 다시 만든다
가진 것      데이터 · 문서 · 프롬프트 · 화면 그림  (코드는 없다. 규정상 못 가져온다)
방법         Claude CLI 창 두 개를 띄우고, 준비된 프롬프트를 순서대로 붙여 넣는다
             CLI-A = 데이터 담당(백엔드) · CLI-B = 화면 담당(프론트엔드)
사람          나 = UI/UX + 진행 · 팀원1 = 알고리즘 · 팀원2 = 챗봇
```

**너는 코드를 쓰지 않는다.** 문서를 붙여 넣고, 결과를 보고,
「이건 이렇게 해 줘」 라고 말하는 게 전부다.

## 2. 시작하기 전 준비 (10분)

```
1  빈 폴더를 하나 만든다.  예)  C:\posco-final\
2  그 안에 이 「본선_반출」 폴더를 통째로 복사해 넣는다
3  Claude CLI 창을 두 개 띄운다. 둘 다 그 폴더에서 실행한다
     창 1 = 백엔드   (제목 표시줄에 A 라고 적어 두면 헷갈리지 않는다)
     창 2 = 프론트   (B)
4  팀원 둘에게 문서를 보낸다
     알고리즘 담당 -> 프롬프트/D_알고리즘팀원_요청서.md + 데이터/ 폴더의 CSV 4개
     챗봇 담당     -> 프롬프트/C_챗봇_연동계약.md
```

**두 CLI 가 같은 폴더에서 일한다.** 서로 다른 파일만 건드리도록
`00_공통규칙.md` 에 표가 있으니 그대로 넣으면 된다.

## 4. 프롬프트 붙여 넣는 법

### 첫 번째 (둘 다)

```
1  프롬프트/00_공통규칙.md 파일을 연다
2  전체를 복사한다 (Ctrl+A, Ctrl+C)
3  CLI 창에 붙여 넣고 엔터
```

### 두 번째부터

```
1  해당 프롬프트 파일을 연다
2  전체를 복사해 붙여 넣는다
3  「같이 첨부할 것」 이 적혀 있으면 그 파일들도 같이 넣는다
     - 문서(.md)는 복사해서 붙여 넣기
     - 그림(.png)은 CLI 에 파일을 끌어다 놓거나 경로를 적어 준다
       예)  이미지/main_pc.png 와 이미지/main_mobile.png 도 참고해 줘
```

### 인계할 때

CLI-A 가 이런 문구를 출력한다.

```
[백엔드 -> 프론트] 1차 인계
  assets/db-master.js   자재 743종 · 부서 1 · 설비 14 · 정비계획 156행
  ...
```

**이걸 그대로 복사해서 CLI-B 에 붙여 넣는다.** 그게 전부다.

## 5. 결과를 어떻게 확인하나 (개발을 몰라도 된다)

### 눈으로 보기

CLI 에게 이렇게 말한다.

```
만든 화면을 브라우저로 열어서 보여 줘.
1512px 데스크톱과 430px 모바일 두 가지로 캡처해 줘.
```

캡처가 나오면 **`이미지/` 의 그림과 나란히 놓고 비교한다.**
다르면 「이 부분이 그림과 다른데 맞춰 줘」 라고 말하면 된다.

### 자동 검사

```
verify.py 랑 runtime_check.js 돌려서 결과 보여 줘
```

이렇게 나오면 정상이다.

```
checked 32 files, 0 problems
runtime: checked 13 pages, 0 problems
```

**problems 가 0 이 아니면** 그 내용을 그대로 CLI 에 보여 주고
「이거 고쳐 줘」 라고 하면 된다.

### 숫자가 맞는지

이 숫자들이 나와야 한다. 다르면 데이터가 잘못 들어간 것이다.

```
자재 743품목
발주 필요 120 · 감축 대상 481 · 현 수준 유지 142      (합 743)
보험품 -> 계획품 149 · 계획품 -> 보험품 90 · 회색지대 31
현행 재고 49.7억원 · 감축 가능 29.71억원

발주 마감 초과는 화면마다 세는 단위가 다르다. 둘 다 맞는 값이다
  정비계획 · 주간 리포트   4건    <- 정비계획(WO) 기준. 8건 중 4건이 마감을 넘김
  대시보드                6건    <- 자재 기준. 지금 신청해야 하는 자재가 6종
```

## 6. 팀원과 주고받는 것

### 알고리즘 담당

**준다** (오전 시작할 때)

```
프롬프트/D_알고리즘팀원_요청서.md
데이터/01_부서.csv  02_자재_정본.csv  03_설비.csv  04_정비계획.csv
데이터/스키마.json
```

**말로 한 번 더 확인한다**

> 「기준일은 **2026-09-03** 하나로 갑시다.
>  키는 **자재코드 + 부서코드 두 칸** 다 넣어 주세요.
>  **743행 전건**이어야 화면이 다 보입니다.」

**받는다**

| 언제 | 무엇 |
| --- | --- |
| 1시간 뒤 | 판정 CSV (743행) |
| 2~3시간 뒤 | 적정재고 CSV · 정체 CSV · 명세상수.json · 요약값.json |

**받으면 바로 CLI-A 에게 준다.**

```
알고리즘 담당한테 받은 CSV 야. 데이터/ 에 넣고 자산을 다시 만들어 줘.
743행인지, PK 가 두 칸인지, 요약값이 행에서 센 값과 같은지 확인해서 알려 줘.
```

**늦어도 괜찮다.** 반출해 온 CSV 로 이미 다 만들 수 있다. 나중에 갈아끼우면 된다.

### 챗봇 담당

**준다** (오전 시작할 때)

```
프롬프트/C_챗봇_연동계약.md
```

**말로 한 번 더 확인한다**

> 「CORS 에 **`"null"`** 꼭 넣어 주세요. 파일로 열어서 시연할 거라
>  이게 없으면 챗봇이 통째로 안 됩니다.
>  그리고 **응답 예시 JSON 한 건**만 먼저 주시면 화면 쪽은 서버 없이도 붙일 수 있어요.」

**받는다**

| 언제 | 무엇 |
| --- | --- |
| 바로 | 서버 주소 · 포트 |
| 붙이기 전 | `result` 응답 예시 JSON 한 건 |
| 색인 끝나면 | `/api/health` 가 200 을 준다는 확인 |

**챗봇이 안 붙어도 시연은 된다.** 화면이 자동으로 시연 모드로 떨어진다.
서두르다 틀린 것을 붙이는 것보다 안 붙이는 게 낫다.

## 7. 막혔을 때

| 증상 | 이렇게 말한다 |
| --- | --- |
| 화면이 하얗다 | 「브라우저 콘솔 오류를 확인해서 고쳐 줘」 |
| 표가 비어 있다 | 「스크립트 로드 순서를 확인해 줘. 어댑터가 DB 보다 먼저 실행되면 빈 배열이 된다」 |
| 숫자가 이상하다 | 「요약을 행에서 다시 세어서 대조해 줘」 |
| 모바일에서 글자가 세로로 쌓인다 | 「flex 자식에 nowrap 이 빠졌다. 디자인 스펙 4.4 를 보고 고쳐 줘」 |
| 그림과 다르다 | 「이미지/xxx_pc.png 와 비교해서 맞춰 줘」 |
| 검사가 실패한다 | 실패 내용을 **그대로 복사해서** 붙여 넣는다 |
| 두 CLI 가 서로 덮어썼다 | 「공통규칙의 파일 소유권 표를 다시 읽고 내 담당 파일만 고쳐 줘」 |
| CLI 가 헤맨다 | **한 단계 뒤로 가서 더 작게 시킨다.** 「화면 하나만 먼저」 |

**절대 하지 말 것** · 두 CLI 에 같은 파일을 고치라고 시키기.
하나가 하던 일이 통째로 날아간다.

## 8. 시연 준비 (마지막 30분)

### 데이터 동결

```
시연 30분 전부터 데이터를 바꾸지 않는다.
알고리즘 담당에게도 미리 말해 둔다.
마지막에 좋아진 값을 넣으려다 화면이 깨지는 일이 제일 흔하다.
```

### 시연 흐름 (5분짜리)

```
1  데이터 근거          "정할 기준 자체가 0건이었습니다"          40초
     -> 0건 네 개를 실제 SQL 결과로 보여 준다
2  대시보드            "그래서 오늘 할 일을 이렇게 내려 줍니다"    40초
     -> 지금 / 이번 주 / 기회 / 검토 네 줄
3  속성값 판단          "AI 가 제안하고 사람이 승인합니다"         60초
     -> 근거 패널을 열어 점수와 산식을 보여 준다
     -> 한 건 승인 -> 대시보드 숫자가 바뀌는 것을 보여 준다   ★
4  적정재고            "속성별로 다른 공식으로 목표재고를 냅니다"   60초
     -> 발주 필요 120 · 감축 가능 29.71억원
5  QR 반납             폰으로 QR 을 찍는다                      60초
     -> 자재 확인 -> 반납 -> 재고가 바뀌고 적정재고 조치도 바뀐다  ★
6  마무리              "근거를 숨기지 않고, 사람의 판단 자리를 남겼습니다"  20초
```

**★ 표시가 이 시스템의 핵심이다.** 화면끼리 값이 흐른다는 것을 보여 주는 순간.

### 자주 받는 질문과 답

| 질문 | 답 |
| --- | --- |
| 현행 대비 몇 % 개선? | **「비교할 현행 기준이 0건이라 그 수치를 만들면 거짓이 됩니다.」** 데이터 근거 화면을 연다 |
| 정확도가 얼마나? | 「정답 라벨이 0종이라 아직 측정할 수 없습니다. 담당자 승인이 첫 라벨이 되고 그때부터 말할 수 있습니다」 |

| 더미 데이터 아닌가? | 「테이블명과 컬럼명은 실제 사내 Oracle 과 같습니다. **접속 정보만 바꾸면 실데이터로 돌아갑니다**」 |

## 9. 오늘의 원칙 세 개

```
1  못 하면 못 한다고 화면에 적는다
     「작업내용 미확인」 「창고 위치 미확인」 「연동 예정」
     지어내면 심사에서 한 번에 들킨다

2  숫자는 한 곳에서만 온다
     화면에 숫자를 적어 두지 않는다. 데이터가 바뀌면 요약만 옛날 값으로 남는다

3  시간이 없으면 자른다
     핵심 3화면 + 데이터 근거면 시연이 된다
     나머지는 「이런 화면도 있습니다」 로 말하면 된다
```
