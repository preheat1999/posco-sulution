**소요 예상 30~40분.** 프론트가 화면을 만드는 동안 병렬로 한다.

## 3-1 · 정비계획 화면 데이터

> ## 할 일
>
> `assets/plan-data.js` 를 만든다. 정비계획 소요 발주 화면이 읽는다.
> **화면에서 마감일을 계산하지 않는다.** 여기서 다 계산해 준다.
>
> 전역 이름은 `PLAN` 하나다. 그 안에 기준일과 목록을 담는다.
> ```
> PLAN.BASE_DATE   기준일
> PLAN.WOS         내 담당 WO. 아래 칸을 가진다
>                    wo eq kind planDate stopStart mats[]
>                    dueDate  발주 마감일
>                    left     남은 일수 (마감일이 없으면 null)
>                    tone     fine / soon / over
>                    ltMean   평균 리드타임
> PLAN.ALL         전체 WO (내 담당 밖까지)
> ```
> 전역을 여러 개 흩뿌리지 마라. 화면이 무엇을 읽어야 할지 헷갈린다.
>
> ### 발주 마감일 산식
>
> ```
> 발주 마감일 = 정지시작일 - (리드타임평균 + 선행일수 + 0.5 x 리드타임편차)
>
> 선행일수   합리화 60 · 대수리 45 · 중수리 21
>           정기수리 14 · 교체휴지 10 · 공정휴지 7
> ```
>
> **선행일수 6종을 다른 곳에도 적어 두지 마라.** 상수는 한 곳에만 둔다.
> 지난 리허설에서 검사기 쪽 값만 옛날 것(교체휴지 14 · 공정휴지 없음)으로
> 남아 있었다. 지금 WO 가 합리화와 대수리뿐이라 **드러나지 않았을 뿐**이다.
>
> ### 건강도 표정
>
> ```
> 남은 일수 7일 이상   fine   웃음   초록
> 3~6일               soon   무표정 주황
> 2일 이하 또는 초과    over   찡그림 빨강
> 마감일 없음(자재 확보) null   웃음   초록     <- 「지금 신청」 으로 세지 마라
> ```
>
> > **`null < 3` 은 자바스크립트에서 참이다.** 마감일이 없는 건을
> > 「지금 신청」 으로 세어 4건이 6건이 됐다. null 을 먼저 걸러라.
>
> ### 입력
>
> ```
> 데이터/04_정비계획.csv     휴지 일정 156행
> 데이터/03_설비.csv         설비 -> 자재
> 데이터/02_자재_정본.csv     리드타임 평균 · 편차
> 데이터/06_적정재고_파생.csv  목표재고 · 필요발주
> ```
>
> **기준일은 `2026-09-03` 하나뿐이다.** `assets/config.js` 의
> `window.CFG.BASE_DATE` 에서 읽고, 다른 곳에 날짜를 적지 않는다.
>
> ### 확인
>
> 만들고 나서 WO 별로 한 줄씩 출력해 눈으로 본다.
> ```
> M260906RM73  2026-09-06 합리화  자재 8  발주 3  마감 -287  over
> ```
> **마감 초과가 3~4건 나와야 시연이 된다.** 전부 여유면 「지금 할 일」 이 없다.

## 3-2 · 검사기 `verify.py`

> ## 할 일
>
> 정적 검사 + **DB 불변식 5개**를 검사하는 파이썬 파일을 만든다.
> 결과는 **콘솔이 아니라 `verify_report.txt` 로 출력**한다
> (Windows 콘솔에서 한글이 깨진다).
>
> ### DB 불변식 5개 (핵심)
>
> ```
> 1  모든 화면의 자재코드가 정본 743 안에 있다
>    따옴표 안만 보지 말고 주소에 박힌 코드까지 본다
>    패턴 \bQ[A-Z]?\d{6,7}\b
>    창고(QFC01) 거래(Q00101)는 자리수가 달라 걸리지 않는다
>
> 2  업무 화면 자재와 분석 화면 자재의 교집합이 비어 있지 않다
>    지난번에 0종이었다. 화면을 넘나드는 흐름이 통째로 끊겨 있었다
>
> 3  db-biz.js 에 품명 · 단가 · 리드타임 · 등급이 없다
>    자재의 정체를 두 곳에서 정의하면 반드시 갈린다
>
> 4  모든 DeptCode 가 부서 표에 있다
>
> 5  요약 숫자가 행에서 다시 센 값과 같다
>    조치 · 판정 · 목표0 · 현행재고액
> ```
>
> ### 곁들여 볼 것
>
> ```
> 파생 행이 정본 키 공간 안에 있고 행 수가 743과 같다
> need · action 을 target 과 stockDept 로 다시 계산해도 같다
> 발주 신호 red · yellow · green 이 모두 있다 (건강도 얼굴 3종)
> QS 접두어 자재는 배제이거나 보험품(QS 확정)이다
> BASE_DATE 가 config.js 한 곳에만 정의돼 있다
> 어댑터가 DB 보다 먼저 로드되지 않는다
> 소스에 제어문자(0x08 · 0x00 · 0x1b)가 박혀 있지 않다
> em-dash(U+2014) · en-dash(U+2013) 가 없다
> 순수 검정 #000 이 없다
> 없는 클래스(.shell .ptitle .psub .btn-primary)를 쓰지 않는다
> CSS 에 정의되지 않은 클래스를 HTML 이 쓰지 않는다
> API 키 · 비밀번호 패턴이 소스에 없다
> ```
>
> ### 제어문자 검사를 반드시 넣어라
>
> 셸 heredoc 으로 정규식을 넘기면 `\b` 가 **실제 백스페이스(0x08)** 로
> 바뀌어 들어간다. 파이썬도 오류를 내지 않고 그냥 **아무것도 매치하지 않는
> 정규식**이 된다. 검사가 조용히 통과해 버린다.
> 지난 리허설에서 자재코드 검사 두 줄이 정확히 그 상태였다.
>
> **패치 스크립트는 heredoc 으로 넘기지 말고 파일로 만들어 실행해라.**
>
> ### 만들고 나서
>
> **일부러 깨뜨려서 실패하는 것까지 확인해라.**
> ```
> 화면에 없는 코드 'Q9999999' 를 넣어 본다        -> 불변식 1 이 잡아야 한다
> db-biz.js 에 name: '가짜' 를 넣어 본다          -> 불변식 3 이 잡아야 한다
> 요약의 목표0 을 999 로 바꿔 본다                -> 불변식 5 가 잡아야 한다
> ```
> 셋 다 잡히면 되돌리고, 「0 problems」 를 확인한다.
>
> 통과만 보고 넘어가면 **검사기가 아무것도 안 보고 있어도 알 수 없다.**

## 3-3 · 렌더 검사기 `runtime_check.js`

> Node 로 화면 13개를 실제로 렌더해 확인한다.
> 헤드리스 크롬으로 각 화면을 열고
>
> ```
> 콘솔 오류가 있는가
> 표가 비어 있는가 (tbody 행이 0)
> 「undefined」 「NaN」 「null」 이 화면 글자에 나오는가
> 가로 스크롤이 생기는가 (scrollWidth > clientWidth)
> ```
>
> 를 보고 `runtime_report.txt` 로 낸다.
>
> **주소에 `?notour=1` 을 붙여라.** 안 그러면 첫 방문 안내가 화면을 덮는다.
>
> ### 좁은 화면을 찍을 때의 함정
>
> 헤드리스 크롬은 창 너비를 **약 500px 아래로 못 내린다.**
> `--window-size=430,900` 을 주면 500px 로 렌더한 뒤 430px 만 잘라 보여 준다.
> 오른쪽이 잘린 것처럼 보이는 **가짜 스크린샷**이 나온다.
>
> 430px iframe 을 넉넉한 창 안에 넣고 찍어라.
> ```
> <iframe src="화면" style="width:430px;height:2400px;border:0"></iframe>
> ```
> 문서 폭은 iframe 안에서 `documentElement.scrollWidth` 로 잰다.
