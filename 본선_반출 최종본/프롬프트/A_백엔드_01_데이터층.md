# A · 백엔드 01 · 데이터층 만들기

**소요 예상 20~30분.** 이게 끝나야 프론트가 화면을 붙일 수 있다.
`00_공통규칙.md` 를 먼저 넣고 이걸 넣는다.

---

> 너는 **백엔드 담당 CLI** 다. 위 공통 규칙의 「백엔드 CLI 가 소유」 목록만 건드린다.
> 화면(`*.html`)과 `shell.css` 는 다른 CLI 가 만들고 있으니 손대지 마라.
>
> ## 할 일
>
> `본선_반출/데이터/` 의 CSV 를 읽어 브라우저가 바로 쓸 자산 두 개를 만든다.
> **생성기는 파이썬 파일 하나(`build_master_db.py`)로만 만든다.**
> 여러 개로 나누면 한 파일만 옛 값으로 남아서 화면마다 다른 답을 하게 된다.
> 지난 리허설에서 실제로 그랬다 (자재 검색만 보험품 441종, 나머지는 302종).
>
> ## 먼저 읽을 것
>
> ```
> 본선_반출/DB_계약서.md          <- 규격. 이게 전부다
> 본선_반출/데이터/스키마.json      <- 컬럼별 타입. CSV 는 타입을 잃는다
> ```
>
> ## 입력 파일
>
> ```
> 데이터/01_부서.csv              1행
> 데이터/02_자재_정본.csv        743행   <- 1층 정본의 본체
> 데이터/03_설비.csv              14행
> 데이터/04_정비계획.csv         156행
> 데이터/05_속성판정_파생.csv    743행   <- 2층
> 데이터/06_적정재고_파생.csv    743행   <- 2층
> 데이터/07_정체자재.csv         262행   <- 2층
> 데이터/명세상수.json                   <- 산식 · Z · 가중치 · 선행일수
> 데이터/요약값.json                     <- 요약 숫자
> ```
>
> CSV 는 UTF-8 BOM 이다. 파이썬은 `encoding='utf-8-sig'` 로 연다.
>
> ## 만들 것
>
> ### `assets/db-master.js`
> ```
> window.DB_MASTER = { meta, depts, materials, equipment, maintenance };
> ```
> * `meta.asof = '2026-09-03'`, `meta.counts` 에 각 건수
> * `materials` 는 02 CSV 그대로. **PK 는 `q` + `dept`**
> * `equipment.items` 는 세미콜론으로 나눠 배열로
>
> ### `assets/db-derived.js`
> ```
> window.DB_DERIVED = { meta, summary, attr, stock, pool };
> ```
> * `meta.spec` 에 `명세상수.json` 을 통째로 넣는다. **화면이 산식을 여기서 읽는다**
> * `summary` 는 `요약값.json` 을 그대로. 다시 계산하지 말고 실어라
> * `stock[].trend` 는 세미콜론으로 나눠 24개 배열로
>
> ## 타입 복원 (반드시 스키마대로)
>
> CSV 는 전부 문자열로 읽힌다. `스키마.json` 이 시키는 대로 되돌려라.
>
> ```
> num    빈 칸은 null. 정수로 떨어지면 정수, 아니면 실수
> bool   'O' 는 true, 'X' 는 false
> list;  세미콜론으로 나눈 배열. 빈 문자열은 버린다
> str    빈 칸은 null
> ```
>
> **`holdStd` 를 숫자로 되돌리는 것을 잊지 마라.** 이건 설치 수 기준이고
> 보험품 목표 산식의 `max(raw, 설치수기준, 1)` 에 쓰인다.
> 리허설 재현 시험에서 이거 하나가 문자열로 남아 102행이 어긋났다.
> **「돌아간다」 와 「같은 값이 나온다」 는 다르다.**
>
> ## 검산 (생성기 안에 넣어라)
>
> 만들고 나서 스스로 확인하고 결과를 출력한다.
>
> ```
> 1  자재 · 판정 · 재고가 전부 743행인가
> 2  요약의 조치(발주 120 · 유지 142 · 감축 481)를 행에서 다시 세도 같은가
>       조치 = target > stockDept ? 발주 : (target == stockDept ? 유지 : 감축)
> 3  현행재고 합계가 4,974,493,448원인가
>       Σ (price x stockDept)
> 4  모든 dept 값이 부서 표에 있는가
> ```
>
> **하나라도 어긋나면 멈추고 알려라.** 조용히 진행하면 나중에 못 찾는다.
>
> ## 실행 방법
>
> ```
> PYTHONHASHSEED=0 PYTHONIOENCODING=utf-8 python -B build_master_db.py
> ```
>
> `PYTHONHASHSEED=0` 을 빼면 집합 순서가 달라져 결과가 흔들린다.
> Windows 콘솔은 `PYTHONIOENCODING=utf-8` 없으면 한글이 깨진다.
>
> ## 다 만들면
>
> 아래를 그대로 출력해라. 사람이 프론트엔드 CLI 에게 그대로 전달한다.
>
> ```
> [백엔드 -> 프론트] 1차 인계
>   assets/db-master.js   자재 <n>종 · 부서 <n> · 설비 <n> · 정비계획 <n>행
>   assets/db-derived.js  판정 <n> · 재고 <n> · 정체 <n>
>   검산 통과 여부 · <내용>
>   아직 window.DB 는 없다. 다음 단계에서 만든다
> ```

---

## 참고 · 이 단계는 이미 검증됐다

리허설에서 **CSV 만 보고 자산을 다시 만들어 원본과 대조**했다.

```
자재 정본 743행   모든 필드 일치
판정      743행   모든 필드 일치
재고      743행   모든 필드 일치
정체      262행   모든 필드 일치
부서 · 설비 · 정비계획 · 요약 · 명세상수   전부 일치
=> 필드 불일치 0건 · 생성 소요 0.03초
```

그리고 그 재현본으로 화면 13개를 렌더해 **오류 0건 · 불변식 5개 통과**를 확인했다.
**데이터는 충분하다.** 안 되면 데이터 문제가 아니라 타입 복원을 빠뜨린 것이다.
