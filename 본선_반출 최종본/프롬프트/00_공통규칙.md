# 00 · 공통 규칙 (두 CLI 모두에게 맨 처음 넣는다)

> 아래 회색 인용 부분을 **그대로 복사해서** 백엔드 CLI 와 프론트엔드 CLI
> **양쪽 첫 메시지에** 붙여 넣는다. 이걸 안 넣으면 둘이 서로 다른 규칙으로
> 만들기 시작하고, 나중에 합칠 때 전부 다시 해야 한다.

---

> # AI 자재 솔루션 · 공통 규칙
>
> POSCO 해커톤 본선 과제 「스스로 수량을 자제하는 AI 자재 솔루션」.
> 정비용 자재의 속성 판단(보험품/계획품)과 적정재고 산출을 자동화하는 사내 웹앱.
>
> ## 지금 상황
>
> 빈 폴더에서 시작한다. 사전에 만든 코드는 하나도 없다 (대회 규정).
> 대신 **DB 더미 데이터 · 계약서 · 와이어프레임 · 디자인 스펙 · 화면 이미지**가
> 있다. 그걸 보고 오늘 다시 만든다.
>
> **CLI 두 개가 같은 폴더에서 동시에 일한다.**
> 네가 어느 쪽인지는 다음 메시지에서 알려 준다. **자기 담당 파일만 건드린다.**
> 남의 파일을 고치면 상대가 하던 일이 날아간다.
>
> ## 기술 제약
>
> * **순수 HTML / CSS / JS.** 빌드 도구 없다. 파일을 그냥 열어도 돌아가야 한다
> * 외부 라이브러리를 쓸 수는 있다. 다만 **사내망에서 외부 주소가 막힐 수 있으니
>   그것이 없어도 화면이 멈추지 않는지** 확인한다. 지금 계획은 의존성 0 이다.
>   차트도 QR 도 직접 그린다
> * 서버가 없다. 브라우저의 `localStorage` 가 유일한 저장소다
> * 파일명은 전부 영문. 배포 호스팅에서 한글 키가 깨진다
>
> ## 글쓰기 규칙 (어기면 검사기가 잡는다)
>
> * **em-dash(U+2014) 와 en-dash(U+2013) 금지.** 가운뎃점 `·` 을 쓴다
> * **순수 검정 `#000` 금지.** 가장 진한 색은 `#1C1D22`
> * 주석은 한국어로, **무엇을 하는지가 아니라 왜 그렇게 했는지**를 적는다
> * 화면 문구에서 「없음」 대신 **무엇을 하면 되는지**를 적는다
>
> ## 데이터 원칙 (이게 이 프로젝트의 핵심이다)
>
> 1. **자재 하나의 정체는 한 곳에만 있다.** 화면 안에 자재를 적어 두지 않는다
> 2. **PK 는 `Qcode|DeptCode`.** 743개 조합이 전체 모집단이다
> 3. **원본을 절대 덮지 않는다.** 사람이 바꾼 것은 변경 이력으로만 쌓는다
> 4. **현재고를 저장하지 않는다.** `스냅샷 + Σ 트랜잭션` 으로 매번 계산한다
> 5. **요약 숫자를 화면에 적어 두지 않는다.** 산출 결과에서 매번 다시 센다
> 6. **화면은 계산하지 않는다.** 산식과 상수는 명세에서 읽는다
>
> ## 자주 내는 실수 (지난 리허설에서 실제로 겪은 것)
>
> | 실수 | 결과 | 규칙 |
> | --- | --- | --- |
> | `null < 3` 이 참인 걸 잊음 | 마감일 없는 건이 「지금 신청」 으로 세어짐 | null 을 먼저 거른다 |
> | 날짜를 라벨 함수 없이 이어 붙임 | 화면에 「마감 D-null」 출력 | 날짜는 라벨 함수 하나로만 |
> | flex 안 칩에 nowrap 안 줌 | 한글이 한 글자씩 세로로 쌓임 | 칩 · 알약 · 배지 · 탭에 nowrap |
> | 어댑터를 DB 보다 먼저 로드 | 빈 배열이 되고 **오류도 안 남**. 화면은 「대장 없음」 | 스크립트 순서를 지킨다 |
> | 생성기를 여러 개 만듦 | 한 파일만 옛 값으로 남아 화면마다 다른 답 | 생성기는 하나 |
> | 요약만 고치고 행은 안 고침 | 숫자가 서로 안 맞음 | 행에서 다시 센다 |
> | 정규식을 셸 heredoc 으로 넘김 | `\b` 가 백스페이스 문자가 되어 **검사가 조용히 통과** | 스크립트는 파일로 만들어 실행 |
>
> ## 검증
>
> 뭔가 만들 때마다 돌린다. **결과는 콘솔이 아니라 파일로 출력한다**
> (Windows 콘솔에서 한글이 깨진다).
>
> ```
> python verify.py            정적 검사 + DB 불변식
> node runtime_check.js       화면 13개를 실제로 렌더해 콘솔 오류 확인
> ```
>
> **검사를 만들었으면 일부러 깨뜨려서 실패하는 것까지 확인한다.**
> 통과만 보면 검사가 아무것도 안 보고 있어도 알 수 없다.

## 파일 소유권 (충돌 방지)

두 CLI 가 같은 폴더에서 일한다. **아래 표 밖의 파일은 건드리지 않는다.**

### 백엔드 CLI 가 소유

```
assets/config.js          기준일 BASE_DATE 와 도메인 상수
assets/db-master.js       1층 정본        (생성)
assets/db-derived.js      2층 파생        (생성)
assets/db-changes.js      3층 오버라이드
assets/db.js              조회 · 쓰기 API
assets/db-biz.js          업무 거래 상태
assets/plan-data.js       정비계획 화면 데이터 (생성)
build_master_db.py        생성기 (하나뿐이다)
verify.py                 검사기
runtime_check.js          렌더 검사기
```

### 프론트엔드 CLI 가 소유

```
*.html                    화면 13개
assets/shell.css          공통 셸 · 토큰 · 반응형 · 부품
assets/nav.js             사이드바
assets/org.js             조직 트리
assets/popover.js         근거 팝오버
assets/wflow.js           진행 막대
assets/chat.js            챗봇 위젯
assets/tour.js            첫 방문 안내
assets/qr.js              QR 생성
assets/analysis-data.js   화면 어댑터
assets/return-data.js     반납 어댑터
assets/evidence-data.js   근거 화면 데이터
```

### 둘 다 건드리면 안 되는 것

```
본선_반출/                 반입 자료. 읽기만 한다
```

### 경계에서 지킬 것

* **프론트는 `DB_MASTER` `DB_DERIVED` 를 직접 읽지 않는다.** `window.DB` 만 쓴다
* **백엔드는 화면을 고치지 않는다.** 화면이 필요로 하는 게 있으면 API 를 늘린다
* 어댑터(`analysis-data.js`)는 프론트 것이지만 **DB API 만** 쓴다

## 진행 순서 (막히지 않게)

```
0분   양쪽에 이 공통 규칙을 넣는다
      백엔드 · A_백엔드_01 부터
      프론트 · B_프론트_01 부터 (데이터가 없어도 셸은 만들 수 있다)

30분  백엔드가 db-master.js · db-derived.js · db.js 를 낸다   <- 첫 인계
      프론트에게 "DB 준비됐다" 고 말한다

이후  프론트는 화면을 하나씩 DB 에 붙인다
      백엔드는 검사기와 정비계획 데이터를 만든다
```

**프론트는 DB 가 없어도 화면이 뜨게 만든다.**

> `window.DB` 가 없으면 `FALLBACK` 이라는 작은 배열(3~5건)로 그린다.
> DB 가 있으면 그걸 쓴다. 그래야 백엔드를 기다리지 않고 화면을 만들 수 있고,
> 시연 중 스크립트 하나가 안 뜨어도 화면이 빈 채로 남지 않는다.
