# D · 알고리즘 담당 팀원용 · 주고받을 것

**이 문서를 알고리즘 담당에게 그대로 준다.**

---

## 0. 한 장 요약

```
내가 준다   부서 · 자재 · 설비 · 정비계획 원본 CSV 4개 (743종 · 기준일 2026-09-03)
받는다      판정 CSV · 적정재고 CSV · 정체 CSV · 명세상수 JSON · 요약값 JSON
언제        오전 중에 한 번. 오후에 갱신본 한 번
형식        UTF-8 BOM CSV. 컬럼 이름은 아래 표 그대로
PK          Qcode + DeptCode 두 칸을 반드시 넣는다
```

**받는 파일의 행 수는 743이어야 한다.** 하나라도 빠지면 화면이 반쪽만 본다.

## 3. 반드시 맞춰야 할 것

| # | 무엇 | 왜 |
| --- | --- | --- |
| 1 | **기준일 `2026-09-03` 하나** | 지난번에 `connect_both.py` 는 09-07, `engine.py` 는 09-03 이었다. 마감일이 4일씩 어긋난다 |
| 2 | **PK 는 `q` + `dept` 두 칸** | 자재코드만으로는 부서별 재고를 구분 못 한다 |

## 4. 지난번 패키지에서 발견한 것 4가지 (확인 부탁)

이번에도 같으면 같은 자리에서 막힌다.

### 4-1 · 기준일이 둘이다

```
connect_both.py   ASOF = 2026-09-07
engine.py         2026-09-03
```
어느 쪽이 맞는지 정해 달라. 우리는 **09-03** 으로 잡고 있다.

### 4-2 · 폴더 규격이 문서와 다르다

```
engine.py        data/ 아래를 읽는다
connect_both.py  상위 폴더(appropriate_dir 루트)를 읽는다
```
`maintenance.csv` 가 없으면 **오류 없이** 정비계획 연동이 **0건**이 된다.
조용히 비는 게 제일 위험하다. **없으면 멈추게** 해 달라.

### 4-3 · `classify_one` 이 재고 행만 있을 때 터진다

```
(outbound or inbound or stock_rows or {}).get(...)
```
`outbound` 와 `inbound` 가 비고 `stock_rows` 가 리스트면 `.get` 이 없어 예외가 난다.

### 4-4 · 재무효과가 두 값이다

```
부서 기준   3,604만원
전사 기준   18.5억원
```
둘 다 맞는 값이지만 **어느 모집단인지** 반드시 붙여 달라.
화면에 그대로 쓸 때 하나만 쓰면 심사에서 「이게 뭐예요?」 를 듣는다.

## 5. 알고리즘 규격에서 꼭 지켜 줄 것

지난번에 실제로 어긋났던 것들이다.

```
1  안전계수 Z 는 등급별이다 · S 2.58 / A 2.05 / B 1.65 / C 1.28
   하나로 고정하면 안 된다

2  등급 캡(상한) 개념은 없다
   유일한 상한은 리드타임창 부트스트랩 400회의 관측상한이다

3  계획품은 Item Type 으로 정하지 않는다
   Consignment · 일일공급품 · 자가재는 1단계에서 배제-소모품으로 완전히 빠진다
   VMI 는 계획품 점수 +10 신호일 뿐 VMI = 계획품이 아니다

4  순환품(Roll/Roller 계열)은 포함이 아니라 배제다 (배제-순환품)

5  배제가 QS 확정보다 상위 조건이다
   QS 자재는 배제이거나 보험품(QS 확정)이어야 한다

6  선행일수 6종
   합리화 60 · 대수리 45 · 중수리 21 · 정기수리 14 · 교체휴지 10 · 공정휴지 7

7  1단계 판정
   si >= 55 & 차이 >= 15 -> 보험품
   sp >= 55 & 차이 <= -15 -> 계획품
   그 외 회색지대
   신뢰도 |차이| 25 이상 HIGH · 15 이상 MEDIUM · 그 외 LOW

8  7요인 가중치
   F5 공용성 0.50 · F1 핵심설비 0.35 · F3 리드타임 0.05 · F4 대체성 0.04
   F6 고장확률 0.03 · F7 조달난이도 0.02 · F2 고장영향 0.01
```

## 6. 주고받는 순서

```
오전 시작  내가 CSV 4개 + 스키마를 준다
          "기준일 2026-09-03 · PK 는 q+dept · 743행" 을 말로 한 번 더 확인

1시간 뒤   판정 CSV 만 먼저 받는다 (적정재고보다 먼저 나온다)
          내가 743행인지 · PK 두 칸인지 · verdict 값이 5종인지 확인

2~3시간 뒤 적정재고 CSV + 정체 CSV + 명세상수 + 요약값
          내가 요약을 행에서 다시 세어 대조하고 결과를 알려 준다

오후       갱신본이 있으면 한 번 더. 그 뒤로는 고정한다
          시연 30분 전부터는 데이터를 바꾸지 않는다
```

**「시연 30분 전 데이터 동결」 을 미리 합의해 둔다.**
마지막에 좋아진 값을 넣으려다 화면이 깨지는 일이 제일 흔하다.

## 7. 파일을 받으면 내가 하는 확인 (자동)

```
1  743행인가
2  PK(q,dept)가 정본 743 조합과 정확히 같은가
3  verdict 가 5종 안에 있는가
4  action 을 target 과 stockDept 로 다시 계산해도 같은가
5  요약값을 행에서 다시 세도 같은가
6  숫자 컬럼이 문자열로 오지 않았는가
```

**하나라도 어긋나면 바로 알려 준다.** 조용히 넘어가면 시연 직전에 터진다.
