# C · 챗봇 담당 팀원용 · 연동 계약과 규칙

**이 문서를 챗봇 담당에게 그대로 준다.**
서로 뭘 만들었는지 모르는 채로 마지막에 붙이려 하면 반드시 안 된다.
**API 모양을 먼저 못 박고 각자 만든다.**

---

## 0. 결론부터 · 지켜야 할 것 다섯 개

| # | 지켜야 할 것 | 안 지키면 |
| --- | --- | --- |
| 1 | 엔드포인트와 응답 필드 이름을 **아래 그대로** | 화면이 답을 못 읽는다 |
| 2 | CORS 에 `"null"` 을 넣는다 | `file://` 로 연 화면이 전부 차단된다 |
| 3 | 근거를 못 찾으면 `no_answer: true` 로 **명확히** | AI 가 지어낸 답을 사실처럼 보여 준다 |
| 4 | 스트리밍은 **줄 단위 JSON(NDJSON)** | 화면이 진행 단계를 못 보여 준다 |
| 5 | 준비 안 됐으면 `503` | 화면이 「서버 오류」 라고만 뜬다 |

**화면 쪽은 서버가 없어도 동작한다.** 자동으로 시연 모드로 떨어져 준비된
예시 답변을 보여 준다. 그러니 **서버가 늦어도 시연은 깨지지 않는다.**
서두르다 틀린 것을 붙이는 것보다 안 붙이는 게 낫다.

---

## 1. 접속 · CORS

화면은 이 순서로 서버를 찾는다.

```
localStorage 에 저장된 주소가 있으면 그것
file:// 로 열렸으면          http://127.0.0.1:8000
8000 포트에서 서빙 중이면      상대 경로 (같은 출처)
그 외                        http://127.0.0.1:8000
```

**FastAPI 의 CORS 미들웨어를 아래 값으로 설정해 달라.**

| 항목 | 값 |
| --- | --- |
| 허용 출처 | `null` · `http://127.0.0.1:5500` · `http://localhost:5500` · `http://127.0.0.1:8000` · `http://localhost:8000` |
| 허용 메서드 | 전부 |
| 허용 헤더 | 전부 |

**`null` 이 핵심이다.** `file://` 로 연 페이지의 Origin 이 문자열 `"null"` 이다.
이게 목록에 없으면 파일로 열어 시연할 때 **챗봇이 통째로 죽는다.**
`5500` 은 VS Code Live Server 기본 포트다.

다른 포트로 서빙하면 차단된다. 포트를 바꿀 거면 **미리 말해 달라.**

## 2. 엔드포인트 4개

### `GET /api/health`

서버가 살아 있는지. 화면이 켜질 때 한 번 부른다.

```
200  { "ok": true, "docs": 75, "ready": true }
503  아직 색인 중.  { "ok": false, "reason": "indexing" }
```

`503` 을 주면 화면이 「서버가 아직 준비되지 않았습니다」 라고 말하고
잠시 후 다시 시도한다. **200 에 ready:false 를 넣지 말고 503 을 줘라.**

### `POST /api/chat/stream` (핵심)

```
요청
{
  "question": "PFC 창고 반납 규정이 어떻게 되나요?",
  "history": [ {"role":"user","content":"..."}, {"role":"assistant","content":"..."} ]
}
```

`history` 는 **최근 6턴(12개)만** 보낸다. 그 이상은 화면이 잘라서 보낸다.

```
응답 · Content-Type: application/x-ndjson
     한 줄에 JSON 하나. 줄바꿈으로 구분한다. 배열로 감싸지 마라

{"type":"stage","label":"질문 유형 파악"}
{"type":"stage","label":"사내 문서 검색"}
{"type":"stage","label":"근거 정밀 선별"}
{"type":"stage","label":"답변 작성"}
{"type":"result","answer":"...","no_answer":false,"route":"rag",
 "citations":[...],"metrics":{...},"trace":[...]}
```

* `stage` 는 몇 개든 좋다. 화면이 진행 단계로 보여 준다.
  **실측 평균 31초**라 단계 표시가 없으면 사람이 멈춘 줄 안다
* `result` 는 **마지막에 딱 하나**. 이것만 렌더한다
* 오류는 `{"type":"error","detail":"..."}`

### `result` 필드

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `answer` | str | 마크다운. 표 · 제목 · 목록 · 코드 · 굵게 · `[n]` 인용만 쓴다 |
| `no_answer` | bool | **근거를 못 찾았으면 true.** 화면이 다르게 표시한다 |
| `route` | str | `rag` / `smalltalk` / `refuse` 등. 없어도 된다 |
| `citations` | list | 아래 참고 |
| `metrics` | obj | `{ "total_ms": 31000, "citation_coverage": 0.75 }` |
| `trace` | list | `["route(rag)","analyze","retrieve","rerank","generate"]` |

### `citations` 한 건

```json
{
  "index": 1,
  "chunk_id": "docA_p21_c3",
  "file_name": "자재입하 및 저장관리 지침(V45).pptx",
  "source": "자재입하 및 저장관리 지침(V45).pptx > 슬라이드 21 (7.1 MES 계획정지 연계)",
  "snippet": "휴지구분은 AD 대수리, MR 중수리, SD 정기수리, CB 교체휴지, SB 공정휴지, RM 합리화의 6종이다."
}
```

`answer` 안에 `[1]` `[2]` 를 쓰면 화면이 **누를 수 있는 버튼**으로 만든다.
누르면 `snippet` 이 열리고, `chunk_id` 가 있으면 원문 미리보기를 부른다.

**`index` 와 `answer` 안의 번호가 맞아야 한다.** 어긋나면 엉뚱한 근거가 열린다.

### `GET /api/preview?chunk_id=...`

인용 원문을 더 길게. 없으면 만들지 않아도 된다 (화면이 `snippet` 으로 대체).

```
{ "text": "...", "file_name": "...", "page": 21 }
```

### `POST /api/feedback`

답변에 대한 좋아요/싫어요. 없어도 된다.

```
{ "question": "...", "answer": "...", "good": true, "citations": ["..."] }
```

### `GET /api/suggest?limit=6&q=...`

입력 중 추천 질문. 없어도 된다 (화면이 준비된 목록을 쓴다).

```
{ "items": ["PFC 창고 반납 규정은?", "..."] }
```

## 3. 타임아웃과 재시도

```
화면 타임아웃   90초   (실측 평균 31초)
503 을 받으면   잠시 후 재시도
연타 방지       답변 중에는 다음 질문을 못 보낸다
```

**60초 안에 첫 `stage` 가 안 나오면 사람이 포기한다.**
검색을 시작하자마자 첫 stage 를 던져라.

## 4. 무엇을 색인해야 하나

정비 자재 업무 매뉴얼과 규정. 화면이 다루는 주제와 겹쳐야 한다.

| 주제 | 왜 필요한가 |
| --- | --- |
| 자재 입하 · 저장 관리 지침 | PFC 창고 · 입고 · 보관 규정 |
| 자재 반납 절차 | **반납 유형 7갈래 · 창고 · 계정 규칙** |
| 구매요청(PR) 발행 절차 | 설비관리시스템 -> ERP 연계 · Destination Type |
| 공용자재 · 이관 규정 | PFC 180일 · 공용 전환 |
| MES 계획정지 · 휴지구분 | 6종 코드 · 정비 일정 |
| 재고 관리 기준 | 안전재고 · 발주점 (현재 비어 있음을 확인해 줄 근거) |

**화면이 이미 답하는 것과 챗봇이 답하는 것을 나눈다.**

```
화면이 답한다     이 자재의 목표재고는? 지금 발주해야 하나? 어디 있나?
챗봇이 답한다     PFC 반납 규정이 뭔가? 이 경우 어느 창고로 가나? 결재가 필요한가?
```

**숫자를 챗봇에게 묻게 하지 마라.** 화면의 DB 와 챗봇의 문서가 다르면
같은 질문에 두 답이 나온다. 챗봇은 **규정과 절차**를 맡는다.

## 5. 시스템 프롬프트 초안 (그대로 써도 된다)

> 너는 POSCO 정비 자재 업무를 돕는 사내 도우미다.
> 아래 검색된 사내 문서 조각만 근거로 답한다.
>
> **규칙**
> 1. 검색된 조각에 없는 내용은 **절대 지어내지 않는다.**
>    근거가 없으면 「이 질문에 답할 근거를 사내 문서에서 찾지 못했습니다」 라고
>    말하고 `no_answer` 를 true 로 둔다
> 2. 모든 사실 문장 끝에 `[1]` `[2]` 처럼 근거 번호를 붙인다
> 3. 표로 정리할 수 있으면 마크다운 표를 쓴다 (코드 · 구분 · 조건 등)
> 4. **em-dash(U+2014) 와 en-dash(U+2013) 를 쓰지 않는다.** 가운뎃점 `·` 을 쓴다
> 5. 답변은 5문장 안쪽으로 짧게. 표는 예외
> 6. 규정에 예외나 조건이 있으면 **반드시 함께 적는다.**
>    「3일 이내면 원 창고, 넘으면 중앙창고」 처럼 조건을 빼면 현장에서 사고가 난다
> 7. 확실하지 않으면 확실하지 않다고 말한다. 추측을 사실처럼 쓰지 않는다
>
> **말투** · 현장 담당자에게 말하듯 짧고 분명하게. 「~합니다」체.

## 6. 화면이 함께 보내는 맥락

화면마다 지금 보고 있는 것을 전역 변수 `CHAT_CONTEXT` 에 담아 둔다.
칸은 두 개다.

| 칸 | 무엇 | 예 (적정재고 화면에서 자재 하나를 고른 상태) |
| --- | --- | --- |
| `label` | 무엇을 보고 있나 | `Q4039953 Rotary/Swivel Joint` |
| `detail` | 그 상태 요약 | `보험품 · S등급 · 현재고 2 / 목표재고 3 · 창고 QFC01` |

이게 있으면 **질문에 함께 실어 보낸다.** 「이거 반납하려면?」 같은 짧은 질문에
무엇을 말하는지 알 수 있다.

**서버 쪽에서는 `question` 앞에 붙어 오는 것으로 보인다.** 따로 처리할 필요 없다.

## 7. 서로 확인할 것 (붙이기 전에 5분)

붙이는 날 아래를 **같이** 해 본다.

```
1  브라우저에서 http://127.0.0.1:8000/api/health 를 연다      -> ok:true
2  화면을 file:// 로 열고 챗봇을 연다                        -> 「연결됨」 표시
3  「PFC 창고 반납 규정이 어떻게 되나요?」 를 물어본다
     - 진행 단계가 뜨는가
     - 답변에 [1] 이 나오고 누르면 근거가 열리는가
     - 표가 깨지지 않는가
4  「오늘 점심 뭐 먹지?」 를 물어본다                          -> no_answer:true
5  서버를 끈 뒤 다시 물어본다                                 -> 시연 모드로 떨어지는가
```

**5번이 제일 중요하다.** 시연 중 서버가 죽어도 화면이 멈추면 안 된다.

## 8. 챗봇 담당에게 넘겨받을 것

| 무엇 | 언제 |
| --- | --- |
| 서버 주소와 포트 (기본 `127.0.0.1:8000`) | 시작할 때 |
| CORS 에 `"null"` 넣었다는 확인 | 시작할 때 |
| `/api/health` 가 200 을 주는 시점 | 색인 끝난 뒤 |
| 실제 `result` 응답 예시 JSON 한 건 | 붙이기 전 |
| 색인한 문서 목록과 건수 | 붙이기 전 |
| 평균 응답 시간 | 붙이기 전 |

**응답 예시 JSON 한 건**만 있으면 화면 쪽은 서버 없이도 붙일 수 있다.
그러니 그것부터 달라고 하는 게 빠르다.
