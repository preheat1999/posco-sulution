> ## 할 일
>
> 모든 화면이 쓸 껍데기를 만든다. **이게 먼저다.**
> 껍데기를 화면마다 복사하면 메뉴 하나 바꾸는 데 13곳을 고치게 된다.
>
> ### 만들 파일
>
> ```
> assets/shell.css       공통 셸 · 토큰 · 부품 · 반응형
> assets/nav.js          사이드바 (이것 하나가 그린다)
> assets/org.js          조직 트리 (로그인과 리포트 수신자가 같이 쓴다)
> assets/popover.js      근거 팝오버
> assets/tour.js         첫 방문 안내
> index.html             login.html 로 보내는 한 줄짜리 진입
> login.html             부서 · 담당자 선택
> main.html              대시보드 (셸이 도는지 확인용으로 뼈대만)
> ```
>
> ### 페이지 껍데기 (클래스명 고정)
>
> ```html
> <div class="layout">
>   <aside class="side" id="side"></aside>
>   <main class="main">
>     <div class="top">
>       <div class="top-left">
>         <button class="hamb" id="hamb" aria-label="메뉴">☰</button>
>         <div><div class="crumb">부문 · 파트 · 섹션 · 그룹</div><h1>화면 제목</h1></div>
>       </div>
>       <div class="top-right"><span class="pill">요약</span><div class="avatar">이</div></div>
>     </div>
>   </main>
> </div>
> <div class="overlay" id="overlay"></div>
> ```
>
> * **없는 클래스를 만들지 마라** · `.shell` `.ptitle` `.psub` `.btn-primary`
> * 제목은 `.top` 안의 순수 `<h1>` 이다
> * `.overlay` 가 없으면 햄버거가 동작하지 않는다
> * 버튼은 `.btn` 이 기본 파란색. 변형은 `soft` · `line` · `sm` 셋뿐이다
>
> ### 사이드바
>
> `nav.js` 하나가 그린다. 각 페이지는 `<head>` 에 `window.PAGE = 'main'` 처럼
> 자기 키만 두고 `<aside class="side" id="side">` 를 **비워 둔다.**
>
> ```
> 관리   Dashboard(main)          데이터 근거(evidence)
> 분석   속성값 판단(attr)         적정재고 분석(stock)
>        정비계획 소요 발주(plan)   주간 리포트(report)
> 업무   구매신청 PR(purchase)     자재반납 QR(return)
> ```
>
> ### 반응형 4단계
>
> ```
> 1180px  다열 그리드 -> 2열 · 스테퍼 줄바꿈
> 960px   사이드바 -> 햄버거 오버레이 · 본문 padding 16px · 2열 -> 1열
> 760px   상단 바 -> 두 줄
> 640px   표 -> 카드 · KPI 1열 · 제목 18px
> ```
>
> ### 좁은 화면에서 반드시 지킬 것 (실제로 당한 것들)
>
> ```
> 1  .top-right{flex:none} 이라 안 줄고 .top-left{min-width:0} 이라 0 까지 눌린다
>    430px 에서 제목이 「속 / 성 / 값 / 판 / 단」 으로 세로로 쌓였다
>    -> 760px 이하에서 .top 을 flex-wrap:wrap 으로 두 줄 만든다
>
> 2  flex 자식은 min-width:auto 라 min-content 폭까지 줄어든다
>    한글은 min-content 가 한 글자다. 「전체」 가 「전 / 체」 가 된다
>    -> .tab .pill .badge .chip 에 white-space:nowrap
>    -> .tabs 는 flex-wrap:wrap 으로 줄을 넘긴다
>
> 3  카드 모드에서 td{display:flex} 라 td 안의 칩도 flex 자식이 된다
>    -> .tablewrap td{flex-wrap:wrap}  .tablewrap td>span{flex:none}
>
> 4  표를 카드로 바꾸려면 모든 td 에 data-label 이 있어야 한다
>    하나라도 빠지면 그 값이 무엇인지 알 수 없다
>
> 5  긴 목록을 좁은 화면에서 전부 그리면 문서 높이가 19만 px 이 된다 (실측)
>    -> 처음 20장만 그리고 「더 보기 (남은 N건)」 버튼
> ```
>
> ### 스크립트 순서 (바꾸면 조용히 깨진다)
>
> ```
> <head> 에 window.PAGE
> 본문 끝에
>   config.js      기준일과 도메인 상수. 가장 먼저
>   org.js         조직 트리
>   nav.js         사이드바. org.js 뒤여야 한다
>   popover.js     근거 팝오버
>   wflow.js       진행 막대 (구매신청 · 자재반납만)
>   chat.js        챗봇 위젯
>   qr.js          QR (material-view 만)
>   db-master.js -> db-derived.js -> db-changes.js -> db.js -> db-biz.js
>   어댑터 (analysis-data / return-data / plan-data / evidence-data)
>   tour.js        마지막
> ```
>
> **어댑터가 DB 보다 먼저 실행되면 빈 배열을 만들고 오류도 안 난다.**
> 화면은 조용히 「대장 없음」 을 띄운다. 지난 리허설에서 실제로 그 버그를 냈다.
>
> ### DB 가 아직 없어도 화면이 뜨게
>
> 백엔드가 `window.DB` 를 만드는 중이다. 지금은 없다.
> 각 어댑터를 이렇게 만든다.
>
> ```
> DB 가 있으면 DB.list() 로 만든다
> 없으면 FALLBACK (3~5건짜리 작은 배열) 로 만든다
> ```
>
> 그래야 백엔드를 기다리지 않고 화면을 만들 수 있고,
> 시연 중 스크립트 하나가 안 떠도 화면이 빈 채로 남지 않는다.
>
