## 2. 확정 속성의 목표재고를 어떻게 아는가

06 의 `target` 은 엔진이 **그 행의 속성으로** 계산한 값 하나뿐이다. 사람이 속성을 바꾸면
그 값은 뜻을 잃지만, 화면은 다시 계산할 수 없다 · μ_LT + SS 에 필요한 소요 이력
(`txn_history.csv` 22,625행)이 반출 데이터에 없다.

그래서 알고리즘 엔진(`feat/algo` 의 `engine.py` · 순수 표준 라이브러리)을 로컬에서 돌려
**속성 두 가지 각각의 목표재고를 미리 구웠다.**

| 단계 | 무엇 | 결과 |
|---|---|---|
| 기준 재현 | 05 판정 579행을 `classification_result.csv` 로 넣고 실행 | 743행 target **743/743 일치** |
| 재현성 | 같은 입력으로 두 번 실행 | 같은 결과 (아래 주의) |
| 전 품목 보험품 | `Type=보험품` 743행 주입 | `targetIns` · `reasonIns` · `signalIns` |
| 전 품목 계획품 | `Type=계획품` 743행 주입 | `targetPln` · `reasonPln` · `signalPln` |
| 검산 | 원래 속성과 같은 쪽이 반출과 같은가 | 보험품 382/382 · 계획품 361/361 |

**주의 · 시드만으로는 결과가 흔들린다.** 엔진의 리드타임창 부트스트랩은
`random.Random(7)` 로 고정돼 있는데도 실행마다 상한이 갈렸다. 원인은 파이썬의
**문자열 해시 무작위화**(프로세스마다 다름)가 소요 이력을 더하는 순서를 바꾸는 것이다.
`PYTHONHASHSEED=0` 을 고정해야 같은 입력에 같은 결과가 나온다. 이걸 모르고 돌리면
같은 데이터로 5~6행이 매번 달라진다.

산출물은 `algo_in/06_목표재고_양속성.csv` → `build_master_db.py` 가 2층에 싣는다.
속성을 바꾸면 목표가 달라지는 행은 **644 / 743** 이다.

## 4. 이번 점검에서 찾은 데이터 사실

### 4-1. 정본 `ceq` 와 엔진의 핵심설비 판단이 11행 다르다

명세의 계획품 규칙 첫 줄은 「핵심설비가 아니면 목표 0」 이다. 그런데 정본
`02_자재_정본.csv` 의 `CriticalEquipment` 가 `X` 인데도 엔진은 핵심설비로 보고
「핵심설비계획품 소요활발(λ1.1)→소량1」 을 내는 행이 **11건** 있다.
엔진은 `equipment_map.csv`(설비-자재 매핑)로 핵심설비를 다시 보기 때문이다.

→ 그래서 화면은 정본 `ceq` 로 목표 0 을 만들지 않는다. **엔진이 낸 값을 쓴다.**
(예전에는 `ceq` 로 0 을 만들었고, 그 11행이 엔진과 어긋났다.)

### 4-2. 반출 06 과 우리 재현이 갈릴 수 있는 자리

`PYTHONHASHSEED` 를 고정하기 전에는 5~6행의 리드타임창 상한이 실행마다 달라졌다.
고정 후 743/743 일치. 기록은 `db/ENGINE_REPRO.txt`.

### 4-3. 확정과 판단은 다른 일이다

`attribute_overrides` 는 append-only 이고 확정은 **seq 하나**로 적는다
(`mtrl.stage.v1.commit`). 그래서 ·

- 판단을 바꿔도 이력이 남는다 (되돌리기 · 역추적 가능)
- 확정 뒤에 새로 판단하면 그 건만 다시 「확정 대기」 가 된다
- 확정 시각을 초까지 남긴다 (화면 두 곳에 같은 값이 보인다)

## 5. 3층 API

```
DB.approveAttr({q, dept, newType, reason})   판단 한 건 (확정 아님)
DB.revertAttr({q, dept}) 또는 (q, dept)      판단 취소
DB.commitAttr()                              여기까지 확정 · {seq, at, n}
DB.commitInfo()                               {seq, at, done, waiting, total}
DB.clearAttr()                                판단 · 확정만 지운다 (반납 · 초안은 남는다)
DB.reset()                                    3층 전부 (사이드바 「시연 초기화」)
```

행에서 읽는 값 ·

| 필드 | 뜻 |
|---|---|
| `type` | **다른 화면이 쓰는 속성** · 확정된 판단만 반영 |
| `judged` | 사람이 고른 값 (확정 여부와 무관) |
| `pending` | 확정 대기인 판단 행 |
| `committed` | 이 행의 판단이 확정됐는가 |
| `targetNow` | 확정 속성의 목표재고 (엔진이 구운 값) |
| `reasonNow` · `signalNow` | 그 속성의 산식 근거 · 신호 |
| `targetIns` · `targetPln` | 속성별 목표 · 「바꾸면 얼마가 되는지」 미리보기용 |
| `stale` | 확정 속성이 06 의 속성과 다르다 (목표를 다시 잡았다) |
